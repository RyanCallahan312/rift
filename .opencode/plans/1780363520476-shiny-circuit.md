# Implementation Guide: `rift init --worktrees`

## Goal

Add an opt-in Git storage mode enabled by `rift init --worktrees`. Repositories initialized this way should keep Rift's fast COW workspace cloning, but every created rift should also be registered as a real Git worktree sharing one external Git repository.

Default `rift init` and existing inline `.git/` behavior must remain unchanged.

## Target Model

For a root initialized with `rift init --worktrees`, move Git metadata outside the workspace and turn the workspace `.git` entry into a pointer file.

Recommended layout:

```text
~/code/app/
  .git                 # gitdir pointer file
  .rift

<rift-data>/repos/<root-rift-id>/
  git/                 # shared Git common dir: objects, refs, config, hooks
    worktrees/
      <child-rift-id>/ # per-worktree admin dir
```

The root workspace can point directly at the external shared gitdir. Child rifts point at per-worktree admin dirs under `git/worktrees/<rift-id>`.

```text
root .git:
gitdir: <rift-data>/repos/<root-id>/git

child .git:
gitdir: <rift-data>/repos/<root-id>/git/worktrees/<child-id>
```

Use Rift ids for Git worktree admin names to avoid collisions and make cleanup safe.

## Key Constraint

Do not try to use `git worktree add` to populate files. Rift should still use existing `Strategy::copy_directory()` for APFS clonefile and btrfs snapshots. After the COW clone, rewrite only the copied `.git` pointer and create small per-worktree metadata.

Git has no stable porcelain command to "adopt" an existing non-empty directory as a worktree. The implementation will need to create the small worktree metadata directory directly, then validate it with Git commands.

## Data Model

Extend the existing `rift` table instead of splitting tables. This keeps recursive parent queries simple.

Add nullable Git metadata columns:

```sql
ALTER TABLE rift ADD COLUMN git_storage_mode TEXT NOT NULL DEFAULT 'inline';
ALTER TABLE rift ADD COLUMN shared_git_dir TEXT;
ALTER TABLE rift ADD COLUMN git_worktree_dir TEXT;
```

Meanings:

- `git_storage_mode`: `inline` or `shared_worktrees`.
- `shared_git_dir`: set on roots initialized with `--worktrees`; descendants inherit by walking to the root.
- `git_worktree_dir`: set on child rifts registered as Git worktrees.

Update `Record` in `crates/core/src/registry.rs` to include these fields, or add a `GitStorage` struct if that is cleaner.

Registry functions to update:

- `Registry::open()` migration/DDL.
- `insert_root()` should accept a storage mode and optional shared gitdir.
- `insert_child()` should accept optional worktree gitdir.
- `record_at()`, `record_id()`, `subtree()`, and `active_paths()` should select any new fields needed by cleanup.
- Add helper methods to get all records for a root when pruning worktree metadata.

## Public API

Add a small init options surface while preserving existing convenience methods.

```rust
pub struct Init {
    pub at: PathBuf,
    pub worktrees: bool,
}
```

Recommended methods:

```rust
impl Manager {
    pub fn init(&mut self, at: impl AsRef<Path>) -> Result<InitOutcome>;
    pub fn init_with_progress(&mut self, at: impl AsRef<Path>, progress: impl FnMut(InitProgress)) -> Result<InitOutcome>;

    pub fn init_options_with_progress(&mut self, input: Init, progress: impl FnMut(InitProgress)) -> Result<InitOutcome>;

```

Existing methods should delegate with `worktrees: false`.

`Manager::create()` should not gain a public flag. It should infer behavior from the registered root's `git_storage_mode`.

## New `worktree.rs` Module

Create `crates/core/src/worktree.rs` for shared-gitdir mode. Keep Git layout logic out of `Manager`.

Responsibilities:

- Compute external shared gitdir path.
- Convert a root repo to external shared-gitdir mode.
- Register a COW-cloned destination as a linked worktree.
- Remove Rift-owned worktree metadata.
- Validate Git can see the result.
- Resolve and write `.git` pointer files.

Suggested API:

```rust
pub(crate) struct SharedGitRoot {
    pub(crate) git_dir: PathBuf,
}

pub(crate) struct RegisteredWorktree {
    pub(crate) git_dir: PathBuf,
}

pub(crate) fn shared_git_dir_for(root_id: &RiftId) -> Result<PathBuf>;
pub(crate) fn initialize_root(path: &Path, root_id: &RiftId) -> Result<SharedGitRoot>;
pub(crate) fn register_cow_clone(root_git_dir: &Path, source: &Path, destination: &Path, id: &RiftId) -> Result<RegisteredWorktree>;
pub(crate) fn remove_registered_worktree(git_dir: &Path) -> Result<()>;
pub(crate) fn prune(root_git_dir: &Path) -> Result<()>;
```

Use `dirs::data_local_dir()?.join("rift").join("repos")` for the external repo base so it is colocated with the existing default SQLite database location.

## Git Path Resolution Refactor

Refactor `crates/core/src/git.rs` before implementing worktree mode.

Current problems:

- `check_source()` rejects `.git` files.
- `hide_marker()` writes `path/.git/info/exclude`.
- `detach_destination()` writes `path/.git/HEAD`.

Add resolved Git metadata helpers:

```rust
pub(crate) struct GitDirs {
    pub(crate) git_dir: PathBuf,
    pub(crate) common_dir: PathBuf,
}

pub(crate) fn resolve_dirs(worktree: &Path) -> Result<Option<GitDirs>>;
pub(crate) fn check_source(path: &Path) -> Result<Source>;
pub(crate) fn check_source_allow_worktree(path: &Path) -> Result<Source>;
```

Implementation rules:

- Use `git -C <path> rev-parse --git-dir` and `--git-common-dir` as the source of truth.
- Canonicalize relative gitdir results relative to the worktree path.
- Treat missing `.git` as `PlainDirectory`.
- Default `check_source()` may continue rejecting linked worktree sources for inline mode.
- `check_source_allow_worktree()` should accept valid Git worktree `.git` files for shared mode.

Update Git helpers:

- `hide_marker(path)` should write to `resolve_dirs(path)?.common_dir.join("info/exclude")`.
- `detach_destination(path)` should write to `resolve_dirs(path)?.git_dir.join("HEAD")` for inline mode only.
- Unsafe Git state checks should probe the resolved per-worktree gitdir for `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `BISECT_LOG`, `rebase-merge`, `rebase-apply`, `index.lock`, and `HEAD.lock`.

## `rift init --worktrees` Algorithm

Initial restriction: support only repositories whose selected root currently has a real `.git/` directory. Reject bare repos, submodules, and already-linked worktrees for the first implementation unless explicitly initialized by Rift.

Steps:

1. Resolve the selected target exactly as current CLI does.
2. Verify `target/.git` is a directory and `git -C target rev-parse --show-toplevel` equals target.
3. Run the same unsafe Git state checks as normal init.
4. Run `strategy.initialize_directory()` as current init does.
5. Allocate the Rift root id before writing the marker.
6. Create staging directory under `<data-local>/rift/repos/<root-id>.tmp/`.
7. Move `target/.git` to `<data-local>/rift/repos/<root-id>.tmp/git`.
8. Write `target/.git` as `gitdir: <tmp>/git`.
9. Set the external gitdir's worktree config so Git commands that start from the gitdir know the root worktree:

```bash
git --git-dir <tmp>/git config core.worktree <target>
git --git-dir <tmp>/git config core.bare false
```

10. Validate with:

```bash
git -C <target> rev-parse --git-dir
git -C <target> rev-parse --git-common-dir
git --git-dir <tmp>/git worktree list --porcelain
git -C <target> status --porcelain
```

11. Atomically rename `<root-id>.tmp` to `<root-id>`.
12. Rewrite `target/.git` to the final `gitdir: <data-local>/rift/repos/<root-id>/git` path.
13. Update `core.worktree` to the final target path if the temporary path was embedded.
14. Write `.rift` marker.
15. Hide `.rift` through the resolved common `info/exclude`.
16. Insert root with `git_storage_mode = 'shared_worktrees'` and `shared_git_dir = <...>/git`.

Rollback requirements:

- If moving `.git` fails, abort without registry writes.
- If validation fails after moving `.git`, move the Git dir back to `target/.git` and remove the pointer file.
- If registry insertion fails, remove `.rift` and restore `.git` if still possible.

For an already registered root:

- `rift init --worktrees` on an inline root should return a clear error for the first implementation rather than migrating in place.
- `rift init --worktrees` on an already shared root should behave like current already-initialized init and restore missing `.rift` if needed.

## `rift create` Algorithm In Shared Mode

Update `Manager::create()` after resolving `source` and `root`:

1. Determine root storage mode from registry.
2. If `inline`, keep current behavior.
3. If `shared_worktrees`, run `git::check_source_allow_worktree(&from)`.
4. Create destination with existing `strategy.copy_directory(&from, &destination)`.
5. Replace the copied `.git` entry with a new pointer file and register metadata via `worktree::register_cow_clone()`.
6. Write the new `.rift` marker.
7. Hide marker in source and destination through `git::hide_marker()`.
8. Insert child with `git_worktree_dir` set.

`register_cow_clone()` details:

1. Resolve source `HEAD` commit with `git -C <source> rev-parse --verify HEAD^{commit}`. If unborn, preserve unborn behavior only after adding a dedicated test; otherwise reject unborn shared-mode create initially.
2. Remove copied destination `.git` file/directory.
3. Create `<shared_git_dir>/worktrees/<rift-id>/`.
4. Write destination `.git`:

```text
gitdir: <shared_git_dir>/worktrees/<rift-id>
```

5. Write worktree metadata:

```text
<worktree-gitdir>/gitdir     => <destination>/.git
<worktree-gitdir>/commondir  => ../..
<worktree-gitdir>/HEAD       => <commit-sha>\n
```

6. Preserve source staged state by copying the source worktree's resolved `index` file to `<worktree-gitdir>/index`. Resolve the source index with `git::resolve_dirs(source)?.git_dir.join("index")`; for the externalized root this is `<shared_git_dir>/index`, and for child worktrees it is that child's per-worktree index.
7. Refresh index stat information without changing staged entries:

```bash
git -C <destination> update-index --refresh
```

If the source has no index, initialize the destination index from `HEAD` with `git -C <destination> reset --mixed --quiet <commit-sha>`.

8. Validate:

```bash
git -C <destination> rev-parse --git-common-dir
git -C <destination> rev-parse --git-dir
git -C <destination> symbolic-ref -q HEAD   # should fail for detached HEAD
git -C <destination> status --porcelain
git --git-dir <shared_git_dir> worktree list --porcelain
```

Important correctness note: staged-state preservation is part of Rift's current Git behavior, so shared worktree mode should copy the source index rather than rebuilding it from `HEAD` in the normal case.

## Remove And GC Behavior

Current Rift trash semantics should remain the source of truth.

For shared-mode child rifts:

1. Before moving to trash, collect `git_worktree_dir` values for every row being removed.
2. Move directories to Rift trash as current `trash_rows()` does.
3. Delete only those collected `git_worktree_dir` directories after validating they are under `<shared_git_dir>/worktrees/`.
4. Run `git --git-dir <shared_git_dir> worktree prune`.
5. Delete active registry records as current code does.

Do not use `git worktree remove` as the primary operation because it deletes the worktree directory and conflicts with Rift trash behavior.

For root unregister:

- Keep source directory on disk.
- Remove `.rift` marker.
- Trash descendants as current code does.
- Do not delete the external shared gitdir unless a separate destructive command is introduced.
- Leave root `.git` pointer intact so the repository remains usable.

For `gc()`:

- Existing trash deletion remains unchanged.
- When pruning active rows whose paths were deleted outside Rift, also remove their recorded `git_worktree_dir` metadata.
- Run `git worktree prune` for affected shared roots.
- Never delete worktree metadata unless it is recorded in Rift's registry or named by a Rift id under a Rift-owned shared gitdir.
